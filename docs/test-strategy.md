# テスト戦略

## 1. 方針

- **ロジックは単体テストで厚く、E2E は主要シナリオに絞る**（テストピラミッド）
- バグ修正時は、再現するテストを先に追加してから直す
- テストは 3 OS の CI で毎回実行する

## 2. テストレベル

| レベル       | 対象                                        | ツール                                      | 実行タイミング               |
| ------------ | ------------------------------------------- | ------------------------------------------- | ---------------------------- |
| 単体（Rust） | ファイル I/O、レンダラー、設定、エラー解析  | `cargo test`                                | PR ごと                      |
| 単体（TS）   | UI ロジック、状態管理、補完・ハイライト定義 | Vitest + Testing Library                    | PR ごと                      |
| 結合（Rust） | 実際の plantuml.jar を呼ぶレンダリング      | `cargo test --features integration`         | PR ごと（Java を CI に導入） |
| ゴールデン   | サンプル `.puml` → SVG の出力比較           | Rust テスト + `tests/fixtures/`             | PR ごと                      |
| E2E          | 開く→編集→プレビュー→保存などの主要操作     | WebdriverIO + tauri-driver（Windows/Linux） | PR ごと（main は必須）       |
| 手動受け入れ | 各イテレーションの受け入れ基準              | チェックリスト（`docs/iterations/itN.md`）  | イテレーション終了時         |

## 3. 目標値

| 指標                                  | 目標                                              |
| ------------------------------------- | ------------------------------------------------- |
| Rust 行カバレッジ（`cargo llvm-cov`） | 70% 以上（コアモジュールは 80%）                  |
| TS 行カバレッジ（Vitest）             | 60% 以上                                          |
| E2E シナリオ                          | 各イテレーションの主要受け入れ基準に 1 件以上対応 |

## 4. テストデータ

- `tests/fixtures/` に図種ごとのサンプル（正常系・構文エラー系・大きな図）を置く
- **社内の実際の設計図は使わない**。公開可能なサンプルのみ

## 5. Tauri IPC の扱い

- Rust のコマンド関数は「Tauri に依存しない純粋な関数」と「薄いコマンドラッパー」に分け、純粋関数を単体テストする
- フロントエンドからの `invoke` はラッパーモジュール経由にし、Vitest ではモックする
