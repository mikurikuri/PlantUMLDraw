# ADR-0003: レンダリングはローカルの plantuml.jar を既定とし、社内サーバーは任意設定とする

- 状態: 承認
- 日付: 2026-11-15

## 背景

PlantUML の図を描くには、PlantUML 本体（Java）を実行するか、PlantUML サーバーへ送る必要がある。
社内の設計図は機密情報を含むことがあり、**公開サーバーへ送ってはならない**。

## 決定

- Rust 側に `Renderer` トレイトを定義し、レンダリング方式を差し替えられるようにする。
- **既定はローカル実行**：`java -jar plantuml.jar -pipe -tsvg` に標準入力で図を渡し、SVG を受け取る。
- **サーバー方式**（社内の PlantUML サーバー / Kroki）は、利用者が URL を明示的に設定したときだけ有効にする（イテレーション 5）。既定の URL は持たない。
- Java は同梱せず、利用者に導入してもらう（D2）。見つからない場合は対処方法を画面に表示する。
- 性能が問題になった場合は、JVM を常駐させる方式を検討する。

## 検討した代替案

| 案                                       | 評価                                                        |
| ---------------------------------------- | ----------------------------------------------------------- |
| 公開 PlantUML サーバー                   | Java 不要で手軽だが、設計図が外部に送信されるため不採用     |
| JavaScript 版 PlantUML（ブラウザ内実行） | Java 不要だが、成熟度・速度が未知数。将来の選択肢として残す |
| JRE を同梱                               | 導入は楽になるが配布サイズが大きくなる。将来 jlink で検討   |

## 影響

- 開発・CI 環境には Java 17 以降と plantuml.jar が必要。
- Graphviz が必要な図種（クラス図など）は、PlantUML 1.2023 以降に内蔵された Smetana レイアウト、または Graphviz の導入で対応する。
