# イテレーション 1：MVP「書いて見られる」

| 項目 | 内容                                             |
| ---- | ------------------------------------------------ |
| 期間 | 2026-11-15 〜                                    |
| 状態 | ローカルで受け入れ確認済み・CI での E2E 確認待ち |

## 目的

最小限だが日常的に使える状態にする。フェーズ A（土台づくり）の最後のイテレーション。ここから利用者が実際に動かし、フェーズ B のユースケース洗い出しを始める。

## 設計方針

| 項目           | 方針                                                                                                                                          |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| レンダリング   | `java -jar plantuml.jar -pipe -tsvg -charset UTF-8` を描画のたびに起動（ADR-0003）。30 秒でタイムアウト                                       |
| 描画タイミング | 入力停止後 **300ms** で描画要求。古い要求の結果は捨てる（要求番号で判定）                                                                     |
| エラー解析     | 終了コード 200 のとき標準エラーの `Error line N` を行番号として使う。画面には直前の正常な図を残す                                             |
| plantuml.jar   | MIT 版 1.2026.10 を `vendor/plantuml.jar` に取得（`npm run fetch:plantuml`、SHA-256 検証）。配布物にはリソースとして同梱                      |
| Java の検出    | 設定 → `JAVA_HOME/bin/java` → PATH 上の `java` の順                                                                                           |
| jar の検出     | 設定 → 環境変数 `PLANTUML_JAR` → アプリ同梱リソースの順                                                                                       |
| ファイル I/O   | Rust 側で実施。UTF-8（BOM の有無を保持）、改行コード（LF / CRLF）を読み込み時に判定し保存時に復元。UTF-8 でないファイルはエラーとして開かない |
| 画面           | 上：ツールバー、左：CodeMirror 6、右：プレビュー（`<img>` で SVG を表示し、SVG 内のスクリプトを実行させない）、境界はドラッグで幅変更         |
| 複数図         | 1 ファイルに複数の `@startuml` がある場合、イテレーション 1 では先頭の図だけを表示（複数図はフェーズ B の候補）                               |
| コマンドライン | 引数で渡されたファイルを起動時に開く（「プログラムから開く」と E2E テストで使う）                                                             |

## 確認中に見つけて直した不具合

| 内容                                                           | 原因                                                                                    | 対応                                                                              |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 同梱の plantuml.jar で描画できない（`ClassNotFoundException`） | Tauri のリソースパスが `\\?\C:\...` 表記で、Java がこの表記の jar を読めない            | 起動前に通常のパス表記へ戻す（`simplify_path`）                                   |
| Java のエラーメッセージが文字化けする                          | 日本語 Windows の Java が標準エラーを Shift_JIS で出力                                  | `-Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8` を指定                          |
| エディターで `->` が矢印 1 文字に見える                        | 等幅フォント（Cascadia Code）の合字                                                     | エディターで合字を無効化                                                          |
| 通知が無いとき、編集領域が画面の上半分にしか広がらない         | グリッドの行定義が通知バーの有無でずれる                                                | 縦並びのフレックスレイアウトに変更                                                |
| E2E でファイルを渡せない                                       | msedgedriver が引数を `--c:\...`（`--` 付き・小文字）に変えて渡す                       | `--` 付きのパスも受け付ける                                                       |
| CI で 100 行クラス図の描画が 8.17 秒かかり、結合テストが失敗   | CI の実行環境が遅いうえ、3 件のテストで JVM が同時に起動していた                        | テストを直列実行し、CI では性能の上限を 5 倍に緩める（`PERF_BUDGET_SCALE`）       |
| CI（Linux）の E2E で入力内容が崩れる                           | `'` の入力でエディターが閉じ記号を補う。Linux の WebDriver では日本語の前の空白が落ちる | E2E で入力する文字を括弧・引用符なしの ASCII に限定し、保存結果をバイト単位で比較 |

## 既知の課題

| 内容                                                                                               | 状況                                                             | 当面の対応                                                                                                        |
| -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| GitHub の Windows ランナーで E2E のアプリ起動に失敗する（`DevToolsActivePort file doesn't exist`） | 開発 PC（Windows 11）では成功。CI ログだけでは原因を特定できない | CI の E2E は Linux のみ。Windows の E2E は開発 PC で `npm run test:e2e` を実行して確認する。要望バックログに記録  |
| `npm run check` などのテストで `target/debug/plantumldraw.exe` が画面を含まない版に上書きされる    | cargo のテスト用ビルドが同じ場所に出力するため                   | exe を直接起動する前に `npm run build:debug` を実行する（CONTRIBUTING に記載）。普段は `npm run tauri dev` を使う |

## リスク

- 描画のたびに JVM を起動するため、1 回 0.5 秒前後かかる（事前計測：単純な図 約 0.47 秒、100 行クラス図 約 0.55 秒）。AC1-2 を満たせない場合は JVM 常駐方式に切り替える（ADR-0003 の「影響」に記載済み）。
- Windows での E2E は WebView2 と msedgedriver のバージョンを合わせる必要がある（`npm run fetch:msedgedriver` が自動で合わせる）。
